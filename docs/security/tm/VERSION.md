## What v2 changes

v1 §2–§15 described the Android Accessibility framework as the single, mandatory
foreground-detection and enforcement mechanism. This conflicted with **ADR-013A**
(two-tier detection) and with the Threat Model's own **§16.32**, which had already adopted
the two-tier model and declared the accessibility-only text superseded (with §16.34.4 still
contradicting §16.32.15).

v2 lands the approved reconciliation as a **superset merge**: every approved two-tier revision
is incorporated, and every still-valid original threat/scope/control/risk item that the

## Important framing preserved throughout v2

The two-tier architecture is **approved but not yet built** (an M2 deliverable). The current
delivered build remains Accessibility-only. v2 consistently distinguishes the **current
delivered implementation** from the **approved target architecture** and does not represent any
target-architecture capability (AS-019/AS-020/AS-021, baseline detection, detection-source
selection, lock-interface presentation) as implemented or security-verified. Risk **R-001**
stays Open until the two-tier baseline is implemented and verified.
