## Results

### OV-4 rapid-relaunch race — PASS
`OverlayRaceUiTest` (`am instrument`), 25 bursts × 20 rapid `am start` relaunches (500 launches):

| Metric | Result | Budget (§11) |
|---|---|---|
| ABSENT | **0** | 0 (hard) |
| BEHIND | **0** | ≤ 2% (sub-poll self-heal) |
| TOP (overlay present + focused) | **25 / 25** | — |

The overlay wins the rapid-relaunch race on every burst. Screenshot-confirmed the overlay fully covers
the target app, holds `mCurrentFocus`, and is touch-modal. **No-regression** met (a budget single-OEM
device already clean on the old engine — this does NOT close R-002; the emulator A/B does).

### Detection latency (partial)
Detection lag (foreground event → poll observation) across the run: **~100–370 ms** (n ≈ 30, sub-poll at
P = 400 ms). Full p50/p95/p99 over ≥ 100 transitions is pending a dedicated latency run.

### Poll gating
Confirmed the poll pauses while the device is asleep/locked (`queryEvents` returns nothing) — observed
directly when the phone slept mid-test — matching the §2.4 contract.

## Platform finding — overlay hidden over Settings (INTENTIONAL, documented)
Android **force-hides** `TYPE_APPLICATION_OVERLAY` windows over Settings / permission / sensitive
screens (`mForceHideNonSystemOverlayWindow=true`, `shown=false`). This is the documented
anti-tapjacking feature `setHideOverlayWindows()` / `HIDE_OVERLAY_WINDOWS` (Android 12+; some OEMs
earlier), **not a defect**. Consequence: an overlay-based lock **cannot cover the Settings app** — a
real product gap vs the accessibility approach. **For the lead:** candidate ADR-013B implementation
note / new ADR (§2.2 discovered-constraint) and a `RISK_REGISTER.md` entry (§5.2).

## Method notes (test fixes made to get a valid result)
- **OV-4 target must be a normal app** — `com.android.settings` is overlay-hidden (above), so the test
  target is `com.google.android.deskclock`, launcher component resolved at runtime.
- **Focus read from `dumpsys window`**, not `dumpsys window windows` — on Android 15 `mCurrentFocus` is
  absent from the latter (version-dependent `dumpsys` format; the WP1 "revalidate the grep per lane"
  caveat). Not a coding bug.

com.applock.test/androidx.test.runner.AndroidJUnitRunner`.
